## 一、项目背景与目标

豆瓣的电影短评是一个很适合练手的文本数据集：**文本短、口语化、带明确的情感倾向，而且天然带标签（星级）**。

本项目参考了一个 GitHub 上的开源同类项目（豆瓣 TOP250 短评分析）的思路，但**从数据到代码全部自己做了一遍**：

| 阶段 | 做什么 | 产出 |
|---|---|---|
| ① 数据采集 | 自己写爬虫，从豆瓣公开页面抓影视资料 + 热门短评 | 1131 部候选、1052 部完整、4695 条短评 |
| ② 清洗与特征工程 | 把 JSON 数据库整理成能直接分析的宽表 | `analysis_movies.csv`、`analysis_comments.csv` |
| ③ 可视化 | 用 ECharts + HTML/CSS/JS 做一面数据大屏 | `web/index.html`（离线可开） |
| ④ 文本建模 | 用短评文本预测星级，并诚实评估它到底行不行 | 7 模型对照 + 6 张诊断图 |

**特别说明**：这个项目没有停在"跑出一个准确率"就结束。第 4 步的重点是
**用交叉验证、AUC、基线对照把自己说服一遍**，最后得出的结论其实是否定性的（见第五节），
我认为这比一个漂亮的假分数更有价值。

## 二、数据采集

### 2.1 规模

| 项目 | 数量 |
|---|---|
| 发现到的候选作品 | **1131 部** |
| 抓完整资料 | **1052 部**（其中电影 539、剧集 513） |
| 连评分分布（五星~一星占比）也抓到 | **942 部** |
| 热门短评 | **4695 条**（覆盖 939 部，每部固定 5 条） |
| 豆瓣 Top250 上榜作品 | 122 部 |

### 2.2 采集方式

- **免登录**：全程只用公开页面，没有账号密码，不需要 Cookie。
- **两个采集通道**：电脑端详情页（资料齐全、含评分分布）+ 手机端接口（速度快，但拿不到五星占比）。
- **节奏是刻意放慢的**：每 9 次请求主动休息 180 秒，请求间隔 6~9 秒，
  算下来约 **2 部/分钟**。实测这个节奏能连续跑一整夜不触发验证码。
  > 教训：为了快而调小间隔，一撞墙就是 2~3 分钟（验证码）甚至半小时（全站 403）的停摆，反而更慢。
- 期间确实遇到过 httpx 哈希挑战和 403，靠**换出口网络**恢复，而不是硬刚。

### 2.3 数据质量自检（全部通过）

| 检查项 | 结果 |
|---|---|
| 五星~一星五个占比之和是否≈100% | 偏离超过 1.2 个百分点的：**0 部** |
| `rating_num` 与评分分布是否同进同退 | **0 例外** |
| 短评正文 / 时间 / 作者 是否为空 | **0 条** |
| 每部短评条数 | 固定 5 条，`min = max = 5` |
| 数据库完整性 | `PRAGMA integrity_check` = **ok** |
| 抽样人工核对 | 《肖申克的救赎》9.7 分 / 335 万人评 / 五星 85.4%，与页面逐字一致 |

### 2.4 已知缺口（诚实交代）

| 缺口 | 数量 | 原因 |
|---|---|---|
| 有资料但没有评分分布 | 110 部 | 早期走手机端接口，那个接口不给五星占比 |
| 完全没抓完 | 189 部 | 候选池里排在后面、还没轮到的 |
| 有资料但没有短评 | 113 部 | 冷门条目详情页没展示热门短评 |
| 短评每部只有 5 条 | 全部 | 设计如此：详情页每页只展示 5 条，翻更多会被验证码墙拦 |

⚠️ 另外要注意：**1052 部里只有 539 部是"电影"，另外 513 部是"剧集"**（豆瓣的发现接口把两者混在一起返回）。

## 三、数据清洗与特征工程

清洗脚本 `analysis/01_build_dataset.py`（**只用 Python 标准库**，不依赖 pandas），从数据库生成两张分析表：

| 表 | 规模 | 用途 |
|---|---|---|
| `analysis_movies.csv` | **1052 行 × 60 列** | 作品维度的分析 |
| `analysis_comments.csv` | **4695 行 × 26 列** | 短评维度的分析 |

### 3.1 作品表派生了什么

- **类型**：出现最多的 15 个类型做 one-hot（`genre_剧情`、`genre_喜剧`…），另有 `n_genres`。
- **时间**：`release_year`、`decade`（1950s~2020s 分档）。
- **热度**：`log_votes`（评价人数取对数，因为跨度从几千到几百万）、`votes_band`（10 以下 / 10-100 / … / 100 万以上）。
- **口碑形态**（这套指标是本项目比较有意思的部分）：
  - `good_rate` = 四星+五星占比，`bad_rate` = 一星+二星占比
  - `polarization` = **五星占比 − 一星占比** → 衡量"叫好又叫座"还是"两极分化"
  - `talk_ratio` = 短评数 / 评价人数 → 衡量"看完想说两句的比例"
- **榜单**：`is_top250` 与 `honor_no`（Top250 的具体名次）。
- **短评聚合**：每部作品的 `n_comments`、`avg_cstar`、`std_cstar`、`avg_cvotes`、`avg_clen`。

### 3.2 短评表派生了什么

- `content_clean`：去掉链接、`@某人`、`#话题#`，只保留中文/数字/字母。
- 文本形态：`n_chars`、`n_excl`（感叹号数）、`n_ques`、`n_ellipsis`、`has_emoji`、`is_short`。
- 时间拆解：`create_time` → 年 / 月。
- 标签：`label_top`（5星 vs ≤4星）、`label_pos`（差评 / 中评 / 好评）。

### 3.3 清洗时踩的两个坑

1. **SQLite 里 `year`、`votes` 存的是文本**，直接做除法会报
   `TypeError: unsupported operand type(s) for //: 'str' and 'int'` → 加统一的 `to_i()` / `to_f()` 防御转换。
2. **Top250 的编号有两种写法**：`豆瓣电影Top250#1` 和旧接口的 `豆瓣电影Top250 No.1`。
   一开始只正则匹配 `No\.(\d+)`，结果全军覆没 → 改成 `(?:#|\bNo\.)\s*(\d+)` 才抓全。
   顺带还发现：`honor` 字段里 160 部中只有 122 部真的是 Top250，其余 38 部是年度榜 / 类型榜（如 `2016评分最高日本电影#1`）。

## 四、可视化大屏

### 4.1 成品

技术栈：**ECharts 5.5.1 + HTML + CSS + JavaScript**，**双击 `web/index.html` 就能看，不需要服务器、不需要联网**（ECharts 和地图数据都下载到了本地）。

![数据大屏](../web/预览截图.png)

### 4.2 大屏上有什么

| 区域 | 内容 |
|---|---|
| 顶栏 | **左：筛选条（口径 × 年代）** · 中：标题 · 右：实时时钟 + 数据更新时间 |
| KPI 行（6 组） | 作品总数 1052 · 电影 539 · 剧集 513 · 短评 4695 条 · 豆瓣 Top250 122 · 平均评分 8.85（无卡片底色的大数字） |
| 左列 | 01 类型 TOP10（横向柱）· 02 年代分布（数量柱 + 平均分折线双轴）· 03 短评星级环形图 |
| 中列 | 04 **中国地图**（按短评作者的 IP 归属地着色）· 05 评分 × 评价人数散点图（对数轴） |
| 右列 | 06 制片国家 TOP10 · 07 高分榜 TOP10（**排名表**）· 08 **短评词云**（jieba 分词） |
| 底栏 | 09 短评年份趋势（渐变面积图） |

**交互：顶部筛选条**。口径（全部 / 电影 / 剧集）× 年代（不限 / 1980s / 2010s / 2020s）两个维度，
点一下会即时重画 **01 类型、02 年代、06 国家、07 高分榜** 四张图；
地图、散点、星级、词云、年份趋势保持全库口径（它们回答的是"短评怎么分布"，按作品类型切开反而失去意义）。
例如切到「电影 + 2010s」：高分榜立刻从全库的《大明王朝1566》(9.8) 变成《盗梦空间》《星际穿越》(9.4)——
因为榜单只在电影、且 2010 年代的作品里排。

> 数据侧：筛选所需的 3 种口径 × 4 个年代 = **12 组分组聚合**由 `analysis/02_export_web_data.py` 预先算好写进
> `web/js/data.js` 的 `filters` 字段，前端只是换一份数据重画，不需要重新请求任何东西（离线也能切）。

### 4.3 从图里读出来的东西

- **类型**：剧情一骑绝尘（591 部），喜剧、动画紧随其后。
- **年代**：1980 年代是个高峰（219 部），2010 年代 296 部最高；但 **1990s 和 2000s 平均分掉到 2.72 / 5.13**，
  这是个**假信号**：这两个年代分别只有 **11/38、21/38 部**抓到了评分分布，而全库缺评分分布的 110 部里，
  有 44 部集中在这两个只占作品总数 7% 的年代里 —— 缺数据最严重的两个年代，平均分自然失真。
  （这一点也说明：**大屏上的每一张图都要先问一句"它的分母是谁"**。）
- **评分与热度**：散点呈明显正相关，但**高分不等于高热度**——**9 分以上却不足 10 万人评价的有 346 部，占了全库三分之一**。
  原因也清楚：这批作品的发现矩阵本身就偏向高分片，冷门佳作因此被大量卷进来。
- **词云**：高频词是"剧情 / 故事 / 喜欢 / 世界 / 演员 / 镜头 / 感动 / 结局"，
  说明大家写短评时主要在**描述作品**，而不是**表达打分**——这个观察直接埋下了第五节的伏笔。

### 4.4 为了"能自己改"做的设计

因为要求是"代码简短、注释详细、每段控制什么要交代清楚"，所以：

- 所有配色集中在 `css/style.css` 顶部的 `:root` 变量里，改一处、全屏变
  （点阵浓淡是 `--dot`，所有结构线是 `--line`，**唯一的强调色是 `--accent`**）；
- **配色只分两层：中性 + 一个强调色**。铜金只出现在"选中项、排行榜第一名、评分、地图高值、词云高频、折线"这六个地方，
  其余全是黑灰白；原来的青色主色、卡片发光、彩色描边在 2026-10-20 的改版里**全部删掉**了 ——
  满屏彩色与发光是"模板感"的主要来源；
- 每张图在 `js/charts.js` 里是**一个独立函数**（`buildGenre`、`buildMap`…），想改哪张改哪张；
- 列宽用 `.main-grid` 的 `1fr 1.3fr 1fr` 控制，列内高度用 `grid-template-rows` 比例控制，不写死像素；
- 数据全部来自 `js/data.js` 一个文件，**换数据不用动任何图表代码**；
- **筛选条是"数据 + 状态"两件事**：`data.js` 的 `filters` 存 12 组聚合结果，`charts.js` 里的 `STATE`
  存当前选中的口径/年代，点按钮只改 `STATE` 再调一次 `refreshFiltered()`。

### 4.5 视觉改版的参考来源

大屏的排版语言参考了 awwwards 数据可视化合集里的几个作品（只借鉴**版式与信息层级**，没有照搬它们的 WebGL 动效）：

其中**影响最大的是 Field Rank 的配色纪律**：整屏只用一个强调色，其余靠灰阶和线划分层级。
改版前是"青色发光 + 满屏彩色"，改版后是"近黑底 + 铜金单色强调"。三版对照见 `web/改版对比_20261020.png`。

## 五、文本建模：短评能猜出星级吗

### 5.1 任务怎么定的

拿到短评最大方的一个标签就是**星级**，所以问题很自然：

> **只看一条短评的文字，能不能判断这个人打了几星？**

主任务定为 **5 星（力荐）vs ≤4 星**。

> 为什么不用"≥3 星 = 喜欢"？因为在这份数据里这个标签会变成 **98.4% : 1.6%（4539 : 75）**，
> 意味着"全猜喜欢"就有 98.4% 准确率，任何指标都失去意义。
> 换成 5 星 vs ≤4 星后是 **57.5% : 42.5%（2651 : 1963）**，接近平衡，指标才有解释力。

可用样本 **4612 条**（4695 条里去掉 81 条没打星的，再去掉 2 条正文清洗后为空的）。

**评估方式**（这是本次建模最重要的一条自我约束）：

- **5 折分层交叉验证**，所有指标都是 **out-of-fold** 的，即每条样本都被"没见过它"的模型预测过一次；
- 同时报 **AUC**：准确率会被类别比例带偏，AUC 衡量纯排序能力，不被基线和阈值绑架；
- 每个任务都写明**多数类基线**，不许拿 60% 的准确率邀功。

### 5.2 七种模型横向对比

| 模型 | 准确率 | macro-F1 | **AUC** |
|---|---|---|---|
| TF-IDF 词(1,2) + 线性 SVM | 0.5752 | 0.5655 | 0.6009 |
| TF-IDF 词(1,2) + 逻辑回归 | 0.5880 | 0.5803 | 0.6212 |
| 词频(1,2) + 朴素贝叶斯 | 0.5987 | 0.5800 | 0.6224 |
| TF-IDF 字(2,3) + 线性 SVM | 0.5939 | 0.5829 | 0.6237 |
| **TF-IDF 字(2,3) + 逻辑回归** | **0.6060** | **0.5990** | **0.6465** |
| 词 + 字拼接 + 线性 SVM | 0.5930 | 0.5818 | 0.6223 |
| 词 + 字拼接 + 逻辑回归 | 0.6067 | 0.5991 | 0.6449 |
| —— 多数类基线 —— | 0.5748 | —— | 0.5000 |

三个观察：

1. **字级 n-gram 比词袋好**（AUC 0.647 vs 0.621）。中文短评口语化、新词多，jieba 词典切不准反而丢信息，字组滑窗更稳。
2. **拼接没有更好**（0.6449）。词和字提供的其实是同一份信息，堆在一起只是增加维度。
3. **所有模型都在 0.57~0.61 之间爬**，说明这不是"参数没调好"，而是**信息量本身就到顶了**。

**结论：最好的模型 AUC 0.647、准确率 60.6%，只比"全猜 5 星"高 3.1 个百分点。**

### 5.3 为什么这么弱？换个分界线就明白了

固定模型不变，**只改"好和坏怎么分"**：

![不同分界线下文本的预测力](model_output/fig1_boundary.png)

| 分界线 | 样本 | 基线 | 准确率 | **AUC** |
|---|---|---|---|---|
| 5星 vs 1-2星（极端对立） | 2726 | 0.972 | 0.970 | **0.700** |
| 5星 vs 3星 | 3043 | 0.871 | 0.850 | **0.718** |
| **5星 vs 4星（相邻档）** | 4145 | 0.640 | 0.607 | **0.623** |
| 3星 vs 1-2星 | 467 | 0.839 | 0.816 | 0.515 |
| 4-5星 vs 1-3星（推荐与否） | 4612 | 0.899 | 0.878 | 0.698 |
| 5星 vs ≤4星（主任务） | 4612 | 0.575 | 0.606 | 0.646 |

**AUC 随"态度差距"单调上升**：隔着两档比（5星 vs 3星）有 0.718，挨着比（5星 vs 4星）掉到 0.623，
而 **3星 vs 1-2星只有 0.515 ≈ 瞎猜**——因为这两档在豆瓣语义里都是"不喜欢"，写出来的话几乎一样。

也就是说：**模型不是没用，是"4 星和 5 星"这条线在文本上本来就模糊。**
豆瓣把 5 星叫"力荐"、4 星叫"推荐"，但对普通用户来说，这两个词的区别常常只是今天心情好不好。
**这是标注本身的主观性，不是模型的锅。**

![混淆矩阵](model_output/fig2_confusion.png)

### 5.4 模型到底学到了什么

把逻辑回归的权重排出来看，结果非常好读：

![特征字组](model_output/fig3_features.png)

**最像「5 星」的特征**：`五星`(+2.19)、`！！`(+1.59)、`动画片`(+1.54)、`小时候`(+1.12)、
`温暖`(+1.12)、`牛逼`(+1.05)、`伟大`(+1.02)、`善良`(+1.00)、`完美`(+0.97)、`童年`(+0.95)
→ 情绪外露的形容词 + **怀旧型好评**。

**最像「≤4 星」的特征**：`女主`(-1.44)、`了，`(-1.40)、`无聊`(-1.35)、`这剧`(-1.34)、`观众`(-1.34)、
**`，但`(-1.33)**、`人物`(-1.30)、`套路`(-1.10)、`故事`(-1.08)、**`有点`(-1.07)**、`叙事`(-1.07)、
**`还是`(-1.02)**、`失望`(-1.01)、**`其实`(-0.98)**、`毫无`(-0.93)
→ 除了负面形容词，更多的是 **"，但"、"其实"、"有点"、"还是" 这类转折连词**。

**这是本次建模最有意思的发现**：中文影评的差评习惯是**欲扬先抑**——先夸两句，再"但是……"。
真正的负面情绪被包在礼貌的句式里，**模型抓到的其实是句式结构，而不是情感词**。
这也解释了准确率为什么上不去：一句"其实还不错，但结局差点意思"和一句"其实很棒"，
字面距离非常近。

> **一处需要交代的瑕疵**：权重榜第一名是 `五星`(+2.19)，因为有人在短评里直接把星级写出来了。
> 全量统计：明确提到星级的短评 **150 条（3.25%）**，其中提到"五星/力荐"的 64 条里 59 条（92.2%）确实是 5 星。
> **把这 150 条全部剔除后重跑，AUC 只从 0.6465 变成 0.6425**，几乎没变，所以不影响主结论。
> 但这类"标签泄漏"必须主动查，不能假装没看见。

### 5.5 一个不看文本的基线，把模型比下去了

这是我认为最能说明问题的一组对照：

| 参照 | 准确率 | 说明 |
|---|---|---|
| 恒猜 5 星 | 0.5748 | 绝对下限 |
| 只看"这是哪部电影"（电影 id one-hot + 逻辑回归） | 0.5768 | 几乎等于没看 |
| **同片其他短评的多数票**（严格留一） | **0.6123** | 完全不读文本，只数同片别人打了几星 |
| **文本模型（主任务）** | 0.6060 | **没跑赢上面那个规则** |

**必须诚实说**：我们的文本模型**没有跑赢**一个完全不读文本、只数"同一部电影里别人打了几星"的傻瓜规则。

不过要公平地看：那个规则需要"同片已有若干条短评"，而我们的数据**每部电影平均只有 4.9 条短评**
（939 部里 118 部全是 5 星、39 部一条 5 星都没有），它利用的其实是"这批高分电影口碑都不错"这个先验。
它的意义是**告诉我们：短评文本没有提供额外的判别信息**，而不是说这个规则真能用。

### 5.6 副任务：文本真正擅长的是什么

**（1）三分类（差评 / 中评 / 好评）—— 模型直接躺平**

最优模型 macro-F1 只有 **0.3814**。看图右边的混淆矩阵：**75 条差评里只认对 2 条**，几乎全猜"好评"。
根本原因是样本量：好评 4145 : 中评 392 : 差评 75 ≈ **55 : 5 : 1**，可学习的差评只有 75 条。**不是模型不行，是没料。**

**（2）短评 → 电影题材 —— 这里才是文本的主场**

一开始我按常规做法做"是不是剧情"的二分类，结果模型准确率反而比基线低（因为 90% 的片子都带"剧情"标签，基线 0.90），
说明这个问法本身是坏的。改成**两两对比**（两种题材的电影各取等量短评，问"这条来自哪一部"，基线恰好 50%）：

![题材对比](model_output/fig5_genre.png)

| 对比 | 样本 | 准确率 | AUC | 比基线 |
|---|---|---|---|---|
| 动画 vs 剧情 | 144 | **0.785** | **0.805** | **+0.285** |
| 动画 vs 纪录片 | 144 | 0.708 | 0.783 | +0.208 |
| 纪录片 vs 喜剧 | 228 | 0.689 | 0.757 | +0.189 |

**同一批文本、同一个模型：判题材（+0.285）远好于判态度（+0.031）。**
这是全文最干净的一个对照，也印证了第四节词云的观察。

### 5.7 顺带发现的一条规律：星级越低，写得越长

![星级与长度](model_output/fig4_length.png)

| 星级 | 条数 | 平均字数 | 中位字数 |
|---|---|---|---|
| 1 星 | 30 | 64.9 | 44 |
| 2 星 | 45 | **98.0** | **84** |
| 3 星 | 392 | 75.3 | 52 |
| 4 星 | 1494 | 70.9 | 48 |
| 5 星 | 2651 | 61.2 | **38** |

5 星短评中位数只要 **38 字**，2 星要 **84 字**——**差评者更愿意展开讲道理，好评者往往一句"好看"就走。**
单独用长度做预测的 AUC 是 0.553，弱但显著。

## 六、结论与反思

### 6.1 我们证明了什么

1. **"短评文本 → 星级"是一个弱信号任务。** 最好的模型 AUC 0.647、准确率 60.6%，
   只比多数类基线高 3.1 个百分点，而且**打不过"同片多数票"这个完全不看文本的规则**。

2. **弱的原因不在模型，在数据本身：**
   - 相邻星级（4 vs 5）在文本上几乎无差别（AUC 0.62），隔档才有（AUC 0.72）；
   - 差评表达被"其实 / 但 / 有点"这类**礼貌转折句式**包裹，情感词并不突出；
   - 样本极度偏斜（好评 : 差评 = 55 : 1），差评只有 75 条可学。

3. **同一批文本，"判题材"的判别力远强于"判态度"**（+0.285 vs +0.031）。
   人们写影评时**主要是在描述作品，而不是在表达打分**。

### 6.2 这个项目的价值在哪

- **不是"做出了一个准确率 97% 的情感分析器"**，而是把问题问清楚了：
  一个看起来很自然的任务，到底能不能做、天花板在哪、为什么。
- **方法论上的收获**：学会了用 **交叉验证 + AUC + 基线对照** 三件套给自己泼冷水，
  而不是拿一个训练集分数去汇报。第七节那个"文本模型跑不赢多数票"的对照，就是这套方法逼出来的。
- **工程上的收获**：完整走了一遍「爬虫 → 数据库 → 清洗 → 宽表 → 可视化 → 建模」的数据链路，
  并且每一环都留下了可复现的脚本。

### 6.3 如果继续做

- **换任务比换模型有用**：情感分析在这份数据上就是弱任务；
  改成"短评 → 题材分类""短评 → 是否提到导演/演员""短评 → 是否剧透"，信号立刻强起来（已用题材对比验证）。
- **要更平衡的样本**：现在好评 : 差评 = 55 : 1，需要针对性补采差评（去低分作品的页面抓）。
- **别用星级当"喜欢"**：豆瓣 4/5 星的界限高度主观，任何以此为标签的模型天花板都很低。
  更可靠的做法是用**同一部电影内部**的相对评分，排除影片本身质量的干扰。
- **补数据**：补那 110 部缺评分分布的作品（含《肖申克的救赎》等头部作品），可以让年代/评分分析更干净。
