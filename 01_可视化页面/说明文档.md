## 一、这是什么

一个**可以点击切换的六屏数据可视化页面**，用纯 HTML + CSS + JavaScript + ECharts 写，
**双击就能打开、断网也能演示**，不需要 Node、不需要构建、不需要联网。

| 屏 | 编号 | 内容 | 一句话结论 |
|---|---|---|---|
| 概览 | 01 | 6 组大数字 · 1052 个方块表示数据体量 · 世界地图 · 反直觉发现（37%）· 三条速读 | 这批数据是什么、有多大 |
| 类型与年代 | 02 | 类型 TOP12 · 年代柱+均分线 · 评分×人数散点 · 短评年份趋势 | 类型高度集中，高分≠高分众 |
| 国家与地区 | 03 | 国家 TOP15 横条 · 45 个国家明细（四处列排成 4 列） | 美国+中国+英国+日本占大半 |

## 四、`index.html`：骨架（改布局看这里）

整体只有四层：

```html
<header class="nav">          顶栏：Logo + 六项导航 #navBar + 右侧「筛选」按钮
<div class="views">           六屏的公共父容器（同一位置绝对定位，靠透明度切换）
  <section class="view" id="view-overview"> … </section>
  <section class="view" id="view-genre">    … </section>
  <section class="view" id="view-country">  … </section>
  <section class="view" id="view-comment">  … </section>
  <section class="view" id="view-model">    … </section>
  <section class="view" id="view-rank">     … </section>
</div>
<footer class="foot">         页脚：数据来源 + 一行统计
```

**关键设计：六屏不是「切页面」，而是同一个位置的六个图层。**
`.view` 默认 `opacity:0; visibility:hidden`，加 `.on` 类才显示。
所以六屏尺寸永远一致（都是 1920×1080 的逻辑区域），不会有跳来跳去的问题。

一张图 = 一个空 `<div id="...">`，由 `charts.js` 往里画：

```html
<div class="card">
  <h3><span class="idx">04</span>类型 TOP12<span class="meta">一部作品可属多个类型</span></h3>
  <div class="chart" id="chartGenre"></div>   <!-- 只有 id，没内容 -->
</div>
```

- `<span class="idx">` 是左上角的**序号**，只是装饰，改数字不影响任何逻辑。
- `<span class="meta">` 是右上角的**小注**，想换说法直接改文字。

六屏里所有容器 id 一览（改名要同时改 `charts.js` 的 `draw('...')`）：

```
概览   #scaleBar #chartWorld #finding #overviewNotes
类型   #chartGenre #chartDecade #chartScatter #chartYear
国家   #chartCountry #countryList
短评   #chartWord #chartStarDual #samples
建模   #modelVerdict #chartModelBar #wordsDuo #chartConfusion
榜单   #rankList #rankAll #rankNote
```

## 五、`css/style.css`：外观（改配色/比例看这里）

### 5.1 先改这四个变量，全站换肤

在文件最顶部 `:root` 里：

```css
--bg:        #0a0b0d;   /* 页面底色 */
--surface:   #101317;   /* 卡片底色 */
--line:      rgba(255,255,255,.08);  /* 所有细线/边框 */
--hot:       #ff6b4a;   /* 唯一强调色：珊瑚橘 */
--text:      #eef1f4;   /* 主文字 */
--text-dim:  #9aa1a8;   /* 次要文字 */
--text-mute: #61686f;   /* 注释文字 */
--radius:    2px;       /* 圆角，越小越"硬朗" */
```

**整套设计只有两种颜色：白（各种灰度的白）+ 珊瑚橘。** 这是它看起来「高级」的核心原因：
没有第二种彩色、没有发光、没有阴影。想换主色只改 `--hot` 一处即可。

### 5.2 字体与字号

```css
/* 2026-10-20 换字体：原来全站宋体（SimSun），在近黑底上笔画发虚、小字糊成一片 */
--font-sans:  "Noto Sans SC","Microsoft YaHei","PingFang SC",…,sans-serif; /* 打底：思源黑体 */
--font-serif: "Noto Serif SC","Source Han Serif SC","Songti SC","SimSun",serif; /* 只给品牌名用 */

--fs-mini: 11px;   /* 极小的编号、单位 */
--fs-cap:  12px;   /* 说明性小标签 */
```

规则只有两条：

1. **黑体打底、宋体点缀。** `html,body` 走 `--font-sans`（思源黑体），只有左上角品牌名
   和卡片标题 `.card > h3` 用 `--font-serif`。这两个字体本机 `C:\Windows\Fonts` 里都有
   （`NotoSansSC-VF.ttf` / `NotoSerifSC-VF.ttf`，都是可变字体），离线能用；没装的系统会退到
   微软雅黑 / 苹方，仍然是黑体观感。
2. **图表字体要跟着改。** `js/charts.js` 顶部的 `FONT` / `FSANS` 两个常量必须和 CSS 里的
   `--font-serif` / `--font-sans` **写完全一样的字体名**，否则图表里的文字会忽然变成另一种字体。

字号方面：全站最小字从 9px 抬到 11px（1920 画布投到 1080 屏是 1:1，9px 在普通显示器上
已经快认不出了），正文普遍 +1~2px。想整体放大有两个办法——改 `--fs-mini` / `--fs-cap`
两颗「全局字号」变量，或者直接在浏览器里 `Ctrl + 滚轮`（页面会等比缩放，最省事）。

**注意：`font-size` 很小的元素仍要显式写 `-webkit-text-stroke: 0`**，否则会被标题的描边规则压糊。
（换字体后标题已经不再用描边，这条更多是留给以后改字体时兜底。）

### 5.3 六屏的网格比例

每一屏内部都是一个 CSS Grid，改宽度比例就改 `grid-template-columns`：

| 屏 | 选择器 | 现在的比例 | 改它会怎样 |
|---|---|---|---|
| 概览 | `.ov-body` | `1.45fr 1fr` / `1fr .8fr` | 地图更大或右侧发现区更大 |
| 类型与年代 | `.grid-3` | 三等分 + `.card.wide` 236px | 一行高度 |
| 国家 | `.country-body` | `2.4fr 1fr` | 横条更长 / 明细更宽 |
| 短评 | `.comment-body` | `1fr 1.25fr` | 词云变大或右侧内容变宽 |
| 建模 | `.model-body` | `1.15fr 1fr 1fr` | 三列宽度 |
| 榜单 | `.rank-body` | `1fr 1fr` | 两榜平分 |

> **踩过的坑**：`.rank-list` 必须写 `grid-auto-rows: minmax(0,1fr)`。
> 写成 `1fr` 时行高按内容撑开，30 行会把卡片顶破。

### 5.4 概览页那 1052 个方块

`.block-grid` 是 `repeat(40,7px)` + `gap:2px` 的 CSS Grid，`main.js` 里生成 1052 个 `<i>`，
每 100 个染成橘色（`i.mark`）——第几个方块就是第几部作品，纯粹用来看"数据量有多大"。

## 六、`js/charts.js`：每张图怎么画（改图看这里）

### 6.1 公共三件套

```js
const D = window.DASH_DATA;        // 所有数据都在这里，来自 data.js
const FX = { accent:'#ff6b4a', text:'#eef1f4', dim:'#9aa1a8', … };  // 图表配色（CSS 变量管不到 canvas，得在这里再写一份）
const FSANS = '"Noto Sans SC",…'; // 图表字体：必须和 CSS 的 --font-sans 同名
```

**改图表颜色改 `FX`，改页面配色改 `:root`，两者要人工保持一致。**

`draw(id, option)` 是唯一的画图入口，它做的事是：按 id 找 DOM → 复用已有实例（没有才新建）→ `setOption(option, true)`。

```js
function draw(id, option) {
  const el = document.getElementById(id);
  const chart = CHARTS[id] || echarts.init(el);   // 同一个 id 只 init 一次
  CHARTS[id] = chart;
  chart.setOption(option, true);                  // true = 完全替换而不是合并
}
```

> 为什么要复用？`echarts.init` 同一个 DOM 调两次会报警告并浪费内存；切屏回来时复用实例只需重画。

### 6.2 一个完整的例子：类型 TOP12

```js
function buildGenre() {
  const rows = D.genres.slice(0, 12);             // 数据里已经排好序，取前 12
  draw('chartGenre', {
    grid: { left: 0, right: 46, top: 4, bottom: 0, containLabel: true },
    xAxis: { type: 'value', show: false },         // 横向条形图：数值轴藏起来
    yAxis: {
      type: 'category',
      data: rows.map(r => r.n).reverse(),          // 反转移轴，让第一名在最上面
      axisLine: { show: false }, axisTick: { show: false },
      axisLabel: { color: FX.dim, fontSize: 12, fontFamily: FONT }
    },
    series: [{
      type: 'bar', barWidth: 10,
      data: rows.map(r => r.c).reverse(),
      itemStyle: {
        // 只把第一名染成强调色，其它是低对比度灰白
        color: p => (p.dataIndex === rows.length - 1 ? FX.accent : FX.bar),
        borderRadius: [0, 2, 2, 0]
      },
      label: { show: true, position: 'right', formatter: '{c}' }
    }]
  });
}
```

**改这张图的常见需求：**

| 想要 | 改哪 |
|---|---|
| 显示前 20 而不是 12 | `slice(0, 12)` → `slice(0, 20)` |
| 所有柱子都染成橘色 | `color: FX.accent`（去掉三元表达式） |
| 条更粗 | `barWidth: 10` → `14` |
| 显示百分比而不是数量 | `formatter: p => (p.value / D.kpi.works * 100).toFixed(1) + '%'` |

### 6.4 词云为什么要自己画

原本用 `echarts-wordcloud` 插件，但它有一个致命问题：插件要**先量出每个词在目标字号下的像素宽高**再排版，
而在「多屏切换 + `file://` 双击打开」的场景下，它量出来是 0 尺寸 → 100 个词全叠在 (0,0)，
屏幕上是一片空白，而且**不报任何错**。

所以 `buildWord()` 改成用原生 canvas 自己画：

1. 按词频算字号（开方后映射到 `[15, 76]`，2026-10-20 由 13px 提到 15px）；
2. 用阿基米德螺旋（`x = r·cos(θ)·1.6, y = r·sin(θ)`）从中心往外找空隙；
3. 矩形碰撞检测，找到不重叠的位置就落笔；
4. 三档颜色：前 15 个强调橘、中间灰白、后段暗灰 —— **热点只在前排**，视觉层次立刻出来。

改它只需要动两个数：`buildWord()` 里的 `fsMax` / `fsMin`，和 `D.wordCloud` 里取多少个词。

### 6.5 世界地图

```js
function ensureMaps() {
  if (!echarts.getMap('world')) echarts.registerMap('world', window.WORLD_GEOJSON);
}
```

- **不注册会直接报 `map not found`**，所以每张地图函数第一行都调 `ensureMaps()`。
- 色阶 `visualMap` 是 `['#2b333d','#8c4a3a','#e0603f','#ff8a63']`，从深灰蓝到亮橘。
  想让地图更亮，把第一档 `#2b333d` 往上调（比如 `#3a444f`）。
- 地名是英文（GeoJSON 只认英文），中文在 `main.js` 的 `CN` 表里对照，改那里可以换叫法。
- 数据里的 `中国（含港台）` 是三个来源合并的（大陆 218 + 台湾 33 + 香港 33），
  因为 GeoJSON 里台湾和香港没有独立边界，不合并会互相覆盖。

## 七、`js/main.js`：启动与交互（改切屏/缩放看这里）

### 7.1 整体缩放（`fitStage`）

页面所有尺寸按 1920×1080 写死，`fitStage()` 用 CSS `transform: scale()` 整体等比缩放并居中。
所以**在任何分辨率的屏幕上都不会挤变形**，只是整体变大或变小。

### 7.2 切屏（`switchView`）

```js
function switchView(key) {
  // 1. 所有屏都隐藏
  document.querySelectorAll('.view').forEach(v => { v.style.visibility='hidden'; v.style.opacity='0'; });
  // 2. 目标屏显示
  const v = document.getElementById('view-' + key);
  v.style.visibility = 'visible'; v.style.opacity = '1';
  // 3. 32ms 后画图 + 让图表重新量尺寸
  setTimeout(() => renderView(key), 32);
}
```

**为什么用 `visibility` 而不是 `display:none`？**
`display:none` 的容器宽高是 0，ECharts 会按 0×0 创建实例，之后画出来是全空的。
`visibility:hidden` 的容器**保留尺寸**，图表能正确初始化。

**为什么要等 32ms？** ECharts 需要在容器真正有宽高之后才能算布局。

### 7.3 六个屏画哪些图

```js
const RENDER = {
  overview: [buildWorld],
  genre:    [buildGenre, buildDecade, buildScatter, buildYear],
  country:  [buildCountry],
  comment:  [buildWord, buildStarDual],
  model:    [buildModelBar, buildConfusion],
  rank:     []          // 榜单是纯 HTML 表格，不用 ECharts
};
```

想在某屏加一张图：在 `index.html` 里加 `<div class="chart" id="chartNew">`，
在 `charts.js` 里写 `function buildNew(){…}`，再把 `buildNew` 加进这里对应屏的数组。

### 7.5 文案是怎么来的

## 十、已知限制（写报告时如实说明）

1. **数据是快照**：2026-10-14 采集，之后豆瓣上的评分变化不会反映出来。
2. **1052 部里有 110 部没有五星~一星分布**，所以星级双分母条的分母是 942 而不是 1052，页面已注明。
3. **短评每部固定 5 条**（热门排序前 5 条），不代表全部短评；`ip_location` 只有 855/4695 条有值。
4. **词云用 jieba 分词**，专有名词（人名、片名）会被切碎，这是分词器的固有局限。
5. **模型只到 AUC 0.645**，比"看同一部片子其它人的评价"（0.612）好一点点，
   比"瞎猜"（0.500）明显好——这个结论本身比模型更有价值，建模页已经把差距画出来了。
